# Lazy editor components

Updated for the Monaco migration, October 2026.

`CodeBlock.tsx` owns controls, controlled/uncontrolled values and the server-rendered
`<pre>` fallback. It imports `MonacoKernel.tsx` dynamically after mount. Only the
kernel imports Monaco. Pure metrics and language-name resolution stay independent
of the editor runtime.

Reading and editing share one model and editor. Changing mode, theme, wrapping or
language updates that instance; changing the value edits the model, including in
read-only mode. External changes do not emit `onChange`. Unmounting disposes the
editor, model and event subscriptions.

Keep `splitting: true` in tsup. Inspect the entire static import graph of
`dist/index.js`, including shared chunks, to verify that importing an unrelated
component does not load Monaco. The dynamic `MonacoKernel-*.js` chunk is the only
entry that should import `monaco-editor`. Metrics shared with the shell must not
import editor themes or language runtime modules.

Consumers configure the editor worker in their client entry point. See the
[CodeBlock guide](../packages/docs/pages/components/code-block/+Page.mdx).

Regression coverage includes retained models, external updates, callbacks, focus
and disposal. The app browser suite additionally exercises real Monaco editing,
read-only mode, theme changes and worker loading.
