# Resize pointer tracking — 2026-09-30

## Unreleased

ResizeDivider and PanelLayout dividers register their gesture listeners directly
in pointerdown, before React commits an active state. They capture the initiating
pointer so crossing a thin divider or an iframe does not require returning to the
handle. Native window capture listeners also provide a fallback when pointer
capture is unavailable and observe events stopped by child surfaces.

Every move records the latest viewport position. Resize callbacks run at most
once per animation frame, avoiding a backlog of obsolete positions when rendering
is busy. Release applies its final position synchronously before ending the drag.
Cancellation, lost capture, window blur, a missed release, and unmount flush any
pending move and remove listeners, capture, and cursor/selection locks. Only the
initiating pointer can move or finish a gesture. JavaScript cannot update the
layout during a main-thread stall; tracking resumes at the latest delivered
position when the thread becomes available.

PanelLayout continues to compute absolute sizes from the press position and
preserves its keyboard splitter controls. Its pill now follows the pointer during
drag as well as hover. ResizableLayout and Waterfall update their live width refs
immediately so several moves or release before a React render retain the full
travel and final persisted width. The DreamLake sidebar reuses ResizeDivider while
preserving its existing pill and width limits.

Validation: 264 UIKit tests, including burst movement/release before a render,
latest-position frame coalescing, pointer identity and all termination paths.
The DreamLake `tests/resize-drag-preview` fixture exercises row, column, legacy
and sidebar controls in Chromium and WebKit with repeated 65ms main-thread stalls,
iframe crossings, final coordinates, and release outside the handle.

No public skill impact: this changes browser gesture reliability and preserves
component props and task procedures. No public documentation pages or generated
skills change. This source behavior has not been released.

## 2026-11-02 — Dividers move the DOM per frame and commit on release

A PanelLayout divider drag used to commit the tree on every coalesced frame:
`onResize` → `commit` → React state → the whole layout re-rendered, the host's
`onChange` ran, `PersistentPanels` re-measured every slot in a layout effect
(a forced layout mid-commit), and every hosted view re-rendered — per pointer
move. Profiled on the DreamLake dash route, that was all of the drag's script
time; the frame still hit 16.7 ms on a light page but had no headroom on a
heavy one.

Now the divider writes the two adjacent children's `flex-grow` directly each
frame and commits the tree ONCE when the pointer is released. `onResize` and
`onChange` therefore fire once per drag (keyboard steps still commit per key).
Persistent surfaces keep following the boundary during the drag because they
observe the slots' sizes, not the tree; `--panel-x` / `--panel-w` are rebuilt
from the committed ratios at release, so content that reads them lags the drag
by the gesture's length (no consumer does today — PanelLeaf publishes them and
nothing in the kit or DreamLake reads them).

Both dividers also stop measuring their own rect per move: the bar's extent
along the axis the pill rides holds still while it slides, so it is read once
at pointerdown. The per-move read forced a second layout in every frame, right
after the host had moved the column.

Validation: `PanelLayout.test.tsx` pins the mid-drag DOM move with no commit
and the single commit on release; `ResizableLayout` and `resize-drag` tests
unchanged.
